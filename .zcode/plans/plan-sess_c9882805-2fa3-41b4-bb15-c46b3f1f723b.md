# 六项收尾功能实施方案（除 IM 外全做）

## 1. 收件箱最新在前（后端小改）
- core `internal_message_recipient_repo.go` List()：补固定 `Order(desc(created_at), desc(id))`（go-crud 无 sorting 时不追加 ORDER BY，预设生效；客户端传 orderBy 仍可覆盖）。app 收件箱与 admin inbox 同链路同时受益
- 冒烟断言：新通知排第一

## 2. 评论热度排序（后端 + App）
- proto：`interaction/service/v1/comment.proto` 的 `ListCommentRequest` 加 `optional CommentSort sort = 4`；新枚举 `COMMENT_SORT_LATEST=0 / COMMENT_SORT_HOT=1`（protojson 全名传输）
- repo：`comment_report_repo.go` VideoCommentRepo.ListByVideo 加 sort 参数——HOT：`desc(like_count), desc(reply_count), desc(id)`；LATEST：现状；ListReply 楼中楼保持时间升序
- App：comment_service 加 sort 参数；comment_bloc 加 sort 状态（切换重置分页重载）；comment_sheet 标题下加「最热/最新」ChoiceChip 切换

## 3. 创作者趋势图（后端 + App）
- proto：`stats.proto` 加 `rpc ListCreatorTrends(ListCreatorTrendsRequest{optional uint32 days=1}) returns (ListTrendsResponse)`（复用 TrendItem）
- repo：`stats_repo.go` 加 `CreatorTrendRows(ctx, authorID, days)`——仿 TrendRows 的 generate_series，plays/likes 按 `uba_events JOIN sp_videos ON video_id WHERE sp_videos.author_id=$1` 按日计，published 按本人 published_at 落日
- core：DashboardService.ListCreatorTrends——author 强制取 viewer uid（不看他人趋势）
- app BFF：`i_stats.proto` 加 `GET /app/v1/creator/trends`（需登录），business_services 转发（dashboardClient 已存在）
- App：创作者中心渐变卡加 onTap → 新页 `/creator/stats`（全屏路由）：近 7/14/30 天切换 + 自绘柱状图（Container+FractionallySizedBox 范式，无新依赖，plays/likes 双色柱）

## 4. 本地敏感词过滤（后端 + 双前端）
- proto：sysconf.proto `SysConf`/`UpdateSysConfRequest` 加 `sensitiveFilterEnabled=6` + `repeated string sensitiveWords=7`；`interaction_error.proto` 加 `SENSITIVE_WORD_HIT = 304 [(errors.code) = 403]`
- ent：sys_config schema 加 `sensitive_filter_enabled bool default false` + `sensitive_words []string JSON Optional` → make ent；sysconf repo/service DTO 映射补齐
- core：共享 helper `spHitSensitiveWords(ctx, sysConfRepo, texts...)`；三处接入——①CompleteUpload（非草稿时 title/description 命中→强制 REVIEWING，即使人工审核关）②SubmitDraft 同理 ③CreateComment 命中→403 SENSITIVE_WORD_HIT（通知逻辑之前拦截）
- admin：sysconf 页加 Switch（sensitiveFilterEnabled）+ TextArea（sensitiveWords 换行分隔，仿 allowedVideoTypesText）；types.ts 补字段
- App：`api_error_messages.dart` 中央映射加 SENSITIVE_WORD_HIT；发布 `_uploadErrorMessage` 与评论 `localizedCommentError` 各加 case；arb 双语词条 + intl 生成

## 5. 批量审核 + 驳回理由模板（纯 admin 前端）
- **决策：批量走前端循环单条端点**（每条完整走状态机+通知；避免新端点的 Casbin 授权链复杂度——新路径需 apis sync+手动 ApiIds 授权才能用）。ListTable 的 restProps 全透传已验证，直接开 rowSelection
- video/index.tsx：rowSelection + 选中行状态 + 批量操作栏（选中>0 显示：批量通过 Popconfirm / 批量驳回走 ReasonModal）→ 循环 useChangeVideoStatus.mutateAsync，完成后 message 汇总成功/失败数 + 刷新
- ReasonModal 加快捷模板 chips（`video.json` 加 tpl1~tpl5 双语词条：内容违规/质量不达标/封面不当/标题夸大/涉嫌侵权，Modal 内点击填入 TextArea）

## 6. 审计日志页（admin 5 个列表页，后端链路全齐）
- 后端唯一改动：`navigation_service.go` 的 resolvableComponents 白名单加 5 个 Vue component 键（`app/log/{login,api,operation,data_access,permission}_audit_log/index.vue`），否则菜单不下发（剧集冒烟同款坑）
- admin：`types.ts` 加 5 个日志 interface（字段以 audit proto 为准）；hooks 加 5 组 fetch；`pages/app/audit/` 一个通用 `AuditLogList` 组件（ListTable + 分页，列配置按类型注入）+ 5 个薄页（login/api/operation/data-access/permission）；静态回退树加 log 组（与种子 /log 路径同形）；COMPONENT_ALIAS_KEYS 按后端 component 的 normalize 规则配 5 条别名；i18n 补 `audit` 模块 ns（列名/空态），menu.log.* 词条已存在无需加
- MVP 页面仅分页列表（不加搜索/导出；csv.ts 的导出助手留待后续）

## 顺序与验证
1. 后端全部（1/2/3/4 的 proto+repo+service）→ make gen → lint+test
2. admin（4/5/6）→ typecheck+lint
3. app（2/3/4）→ analyze+test
4. 冒烟（bin/smoke-v3.sh）：新通知排首；两条评论点赞后 HOT 排序生效；A 拉 /creator/trends 形状正确；admin 开敏感词+词表后 B 发含词评论 403、发布含词标题强制 REVIEWING；admin operation-audit-logs 列表 200
5. 全绿后提交 main

## 边界
审计页不加搜索/导出；敏感词不做词库管理页（走 sysconf）；批量审核不上限（前端循环，量级=页选行数）
